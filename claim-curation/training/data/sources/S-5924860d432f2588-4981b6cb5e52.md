# FLM Qwen3.6-35B-A3B: three `/v1/chat/completions` timings, load time and KV capacity

Sources (C:/code): `flm_resp1.json`, `flm_resp2.json`, `flm_resp3.json` (one FLM server response each; `created` = 1788280352, 1788280378, 1788280405, which is 2026-09-01 16:32-16:33 UTC; file times Sep 1 11:32-11:33 local). Each holds FLM's own `usage` block.

| resp3 | 15 | 87 | 9e-07 | 5.076438528 | 2.954827467576891 | 12.650646 | 6.877119160555121 |

- The first request paid a 34.82 s model load; the next two found the model loaded.
- FLM's `prefill_speed_tps` is prompt tokens divided by TTFT (16 / 5.221 = 3.064), so it includes every fixed cost before the first token.
- Means over the three: decode 6.83 tok/s, prefill 3.12 tok/s. These match F-0026's FLM 1.0.2 baseline ("~6.8 and ~3.1 ... 3 requests"); these files are most likely that baseline (inferred: same day, same count, same means).

## KV capacity

- `kv_token_occupancy_rate_percentage` is exactly (prompt + completion) / 32768 x 100 in all three (80 -> 0.244140625, 105 -> 0.3204345703125, 102 -> 0.311279296875). So the server ran with a 32768-token context, the documented default for Qwen3.6-35B-A3B (default 32k, max 256k; C:/code/FastFlowLM/docs/docs/models/qwen.md:448-449).

## Doubtful

- TTFT here is 5.08-6.91 s for 15-23 prompt tokens. F-0024 reports 9.42 s for 11 tokens, 11.74 s for 12 and 12.30 s for 23 on the same day, and a ~8.8 s constant per request. A two-point fit here (15 -> 5.08 s, 23 -> 6.91 s) gives about 0.23 s per token plus about 1.6 s. The F-0024 runs used a capture shim over `xrt_coreutil.dll`, which may explain the gap (inferred; not tested).
- F-0027 says FLM's per-layer 3 MB state buffer holds KV for `MAX_POSITIONS` = 1024. These responses report a 32768-token KV capacity. Either FLM sizes the state buffers by `--ctx-len`, or the F-0027 capture ran at a smaller context (inferred; not checked).
- Bears on Q-0011: on this machine and day FLM decoded Qwen3.6-35B-A3B at 6.68-6.92 tok/s at a 32k context with under 110 tokens in use, against the vendor's 17.48 tok/s at 1k (v0.9.45, Kraken Point, 96 GB).
