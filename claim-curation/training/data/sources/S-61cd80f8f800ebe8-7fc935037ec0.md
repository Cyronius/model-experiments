# Qwen3.6 35B-A3B on one HX 370: OpenFlowLM (all on NPU) against llama.cpp with and without the ggml-xdna add-on

Sources (C:/code/npu-prefill-engine): `README.md:236-288` ("Against other engines"), `commit 0220722` (2026-10-08 08:17). The old ggml-xdna notes did not cover this README section. Rates are tokens per second at prompt lengths 1k / 2k / 4k / 8k.

## OpenFlowLM, whole model on the NPU

- q4_1: prompt reading 134 / 136 / 139 / 137 tok/s.
- q4_1: reply writing (32 tokens after the prompt) 12.4 / 12.0 / 10.8 / 8.9 tok/s.
- 8-bit weights with 4-bit experts: prompt reading 112 / 116 / 118 / 114 tok/s.
- 8-bit weights with 4-bit experts: reply writing 7.0 / 8.2 / 7.8 / 6.6 tok/s.
- OpenFlowLM's reply speed drops as the prompt grows (12.4 to 8.9 tok/s from 1k to 8k), while the GPU engines hold steady (`README.md:287-288`).

## llama.cpp with the add-on (NPU matmuls, GPU for the rest)

- Q4_K_M, prompt reading: with the add-on 223 / 216 / 259 / 235; GPU alone 223 / 202 / 197 / 202. Lead of up to 1.31x.
- Q8_0, prompt reading: with the add-on 170 / 196 / 199 / 198; GPU alone 181 / 168 / 199 / 187. Lead of up to 1.17x.
- The add-on leaves replies to the GPU, so its reply rows should equal the GPU-alone rows. They differ by up to 14%; the source reads 14% as the noise on any figure in these tables (`README.md:278-280`).
- The NPU cannot take the expert step in this add-on, so only attention and shared weights reach the NPU on this model (`README.md:375-377`).

## Bears on Q-0011

- OpenFlowLM's NPU-only reply rate on the HX 370, 12.4 tok/s at 1k (q4_1), is about 1.8x the FLM 1.0.2 figures of 6.6-7.05 tok/s in Q-0011 Claim B. It is below FLM's published 17.48 tok/s (Kraken Point, v0.9.45).
- OpenFlowLM's prompt rate, 134-139 tok/s flat over 1k-8k, sits inside FLM's published 102-281 tok/s range but does not rise with length as FLM's table does.

## Doubtful

- The source warns: "These are one machine's figures, not a ranking." Quants differ between engines; OpenFlowLM's 8-bit build keeps experts at 4 bits.
- Run date, repeat count, OpenFlowLM commit and NPU power mode are not given. Treat each figure as one draw with about 14% noise.
- In the README Results table the same model in another quant (Ornith 35B, APEX-I-Mini) ran 0.92x with the add-on (`README.md:169`), so the add-on result depends on the file.
